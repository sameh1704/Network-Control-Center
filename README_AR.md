# Network Control Center v1 — نسخة مصدرية تجريبية وظيفية

**مهم: هذه ليست APK مثبتة أو تطبيقًا جاهزًا من دون إعداد.** لا يوجد Flutter أو Android SDK في بيئة البناء الحالية؛ لذلك لا يمكن إنتاج APK هنا أو اختباره على هاتف فعلي. لا تدّعي هذه الحزمة أنها فُحصت على إصدار ESXi الحقيقي لديك.

## الوظائف المتوفرة في الكود
- واجهة أندرويد Flutter: إعداد عنوان خادم التحكم HTTPS ومفتاح الدخول؛ إضافة FortiGate وESXi من شاشة التطبيق؛ قائمة أجهزة مع عرض VMs تلقائيًا تحت كل ESXi؛ حالة VM من الـ API الفعلي؛ تحديث كل 15 ثانية؛ تأكيد قبل التنفيذ.
- الخادم FastAPI: حفظ الأجهزة في SQLite، تشفير كلمات مرور ESXi في قاعدة البيانات باستخدام Fernet، قراءة مخزون الـ VMs عبر pyVmomi، تشغيل VM متوقفة، وإرسال **RebootGuest** الآمن عند توفر VMware Tools، مع سجل للأوامر.
- حالة FortiGate مبنية فقط على الوصول لمنفذ الإدارة، ولا تثبت سلامة الخدمات أو تشغيله بشكل مؤكد.
- إعادة تشغيل FortiGate، إعادة تشغيل ESXi المادي، وتشغيل الخادم المادي المتوقف: **غير مفعلة** إلى حين التحقق من الجهاز وإصداراته والتحكم المادي.
- VM Restart هنا هو **إعادة تشغيل نظام الضيف (Graceful RebootGuest)** وليس Hard Reset؛ ويتطلب VMware Tools؛ لا يتم تنفيذ Hard Reset افتراضيًا.

## متطلبات ضرورية
1. **جهاز مستقل** داخل شبكة الإدارة لتشغيل الخادم، متاح بعد عودة الكهرباء ويفضل UPS.
2. VPN يعمل على الهاتف للوصول لشبكة الإدارة. لا تكشف المنفذ 8000 أو واجهات FortiGate/ESXi مباشرة للإنترنت، ولا تعتمد على VPN يستضيفه FortiGate عندما يكون معطلًا.
3. إعداد HTTPS بشهادة موثوقة للخادم. Android client يرفض HTTP.
4. شهادة CA موثوقة لـ ESXi على خادم التحكم (لا نوقف التحقق من الشهادة). إصدار ESXi 6 قد يستخدم شهادة ذاتية التوقيع؛ يُفضَّل توثيق الشهادة واستبدالها بشهادة موثوقة ومتوافقة أو تركيب سلسلة CA صحيحة؛ تفاصيل التوافق تختلف حسب إصدار 6.x.
5. حساب ESXi بصلاحيات رؤية الـ VMs وتشغيلها وإعادة تشغيل نظام الضيف، حسب المهام المطلوبة.

## تشغيل الخادم
```bash
cd controller
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\\Scripts\\activate
pip install -r requirements.txt
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```
اضبط متغيري البيئة `NCC_API_KEY` (مفتاح عشوائي طويل 32 حرفًا على الأقل) و`NCC_ENCRYPTION_KEY` (نتيجة الأمر الأخير). احفظهما في مدير أسرار أو خدمة نظام محمية؛ لا تحفظهما في مستودع أكواد.

```bash
uvicorn main:app --host 127.0.0.1 --port 8000
```
ضع أمامه HTTPS reverse proxy ببيانات TLS حقيقية، واربط الوصول بـ VPN فقط. للوصول من شبكة VPN إلى FastAPI يمكن ضبط reverse proxy ليمرر إلى localhost؛ لا تفتح FastAPI مباشرة للعامة.

## إعداد الأجهزة في التطبيق
Settings: اكتب HTTPS URL الخاص بخادم التحكم داخل VPN + مفتاح NCC_API_KEY؛ Add device: اختر ESXi أو FortiGate، الاسم، عنوان الإدارة **الداخلي** (private/VPN IP)، المنفذ (عادة 443). ESXi يحتاج اسم مستخدم وكلمة مرور ومسار شهادة CA **على خادم التحكم**؛ تظهر الأجهزة الافتراضية تلقائيًا تحت ESXi. حالة offline تشير إلى VM المتوقفة فقط؛ تعذر الاتصال بالخادم يظهر unknown.

## حدود معروفة
- الخادم يستخدم API key مشتركًا؛ الإصدار الإنتاجي يحتاج هوية مستخدم فردية و2FA ومراجعة الصلاحيات وتحديد معدل الطلبات وعزل شبكة الإدارة.
- عند انقطاع الاتصال ستظهر حالة unknown، لا offline.
- اكتشاف أسماء الـ VMs لا يتطلب عنوان IP مستقلًا لكل VM.
- إضافة أجهزة عامة بعنوان Static Public IP إلى قائمة الإدارة غير مسموح في هذه النسخة حمايةً للواجهات الإدارية.
- سيحتاج اختبار تكامل فعلي مع رقم Build الخاص بـ ESXi 6.x ونموذج FortiGate وإصدار FortiOS وبيئة VPN.

### تحقق سريع من خادم التحكم
من مجلد `controller` وبعد تثبيت requirements وpytest (للاختبار فقط) يمكن تشغيل `pytest -q tests`؛ الاختبارات لا تتصل بأجهزتك. لم يتم اختبار ربط ESXi 6 الحقيقي أو FortiGate في هذه الحزمة.

### لماذا لا يظهر زر تشغيل السيرفر الفعلي عندما يكون مطفأ؟
التحكم بـ Power On على سيرفر ESXi نفسه يتطلب iDRAC أو iLO أو IPMI أو وسيلة إدارة كهرباء متوافقة، بينما تشغيل VM متوقفة يتم عبر API الخاص بـ ESXi إذا كان ESXi نفسه يعمل.

### ملاحظات عن انقطاع الكهرباء
يُنصح بتمكين VM Autostart واختباره على ESXi بعد عودة الكهرباء، وتهيئة shutdown الآمن عبر UPS. إذا انقطع الإنترنت بسبب FortiGate أو الكهرباء فلن يتمكن التطبيق من الوصول للشبكة من الخارج دون مسار إدارة مستقل.
